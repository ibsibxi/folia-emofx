# 这个插件的模型，优势在哪

> 面向：插件商店描述 / 给开发者的说明 / 自己判断要不要继续投入。
> 所有数字都来自本项目的实测与逆向结论，不是宣传口径。

---

## 一句话定位

**「不联网的按歌调音」**：每首歌进来，本地几十微秒算出一条属于它的 EQ 曲线，交给播放器执行。
不是固定预设，不是云端推理，不是大模型。

---

## 一、模型本身的四个硬优势

### 1. 极小 —— 小到可以塞进任何地方

| 项 | 数值 |
|---|---|
| 原模型 `emofxnet.mnn` | 553 KB |
| 蒸馏后纯 JSON 权重 | 590 KB（fp16 可压到 ~150 KB） |
| 计算量 | 132×128 + 128×64 + 64×32 ≈ **2.7 万次乘加** |
| 单次推理 | **< 10 µs**（单核，纯 CPU） |
| 依赖 | **零**。任意语言几十行矩阵乘即可 |

意义：不需要 MNN、不需要 ONNX Runtime、不需要 GPU、不需要 WebAssembly 之外任何运行时。
JS / C++ / Python 里跑的是同一份权重、同一个结果。

### 2. 每首歌一条曲线 —— 而不是逐帧

网易云自己在 `AiModelEffectManager.tryPreload` 里预取**下一首**的结果，说明这条曲线是**切歌时确定**的，不随音频逐帧变化。

意义：
- 音频线程零负担（推理发生在切歌时，不在实时回调里）；
- 不存在"特征提取拖高延迟"的问题，延迟只由 DSP 缓冲决定；
- 可以**预取**：歌还没放，曲线已经算好。

### 3. 输出就是参数 —— 不需要再映射

模型吐出的 32 维里，前 10 维**就是** 10 段 EQ 的 dB 值（31.5/63/125/250/500/1k/2k/4k/8k/16k），单位、量级、粒度（0.1 dB）都对着执行器。

意义：没有"模型输出 → 业务参数"的翻译层，也就没有翻译误差；
曲线本身就是最终产物，可直接展示给用户看。

### 4. 蒸馏误差远低于人耳阈值

| 指标 | 数值 |
|---|---|
| 蒸馏后 10 段平均误差 | **0.37 dB** |
| 单点最大误差 | 0.33 dB |
| 人耳可辨阈值 | ≈ 1 dB |

意义：**精度上等价于原模型**，但体积和依赖都降了一个量级。

## 二、工程上的三个优势（这才是能做成产品的原因）

### 1. 特征只贡献 8–16%，所以不必复刻网易云的特征语义

实测灵敏度：

| 影响来源 | 曲线抖动（平均 std） |
|---|---|
| 情绪 + 流派 | 0.887 dB（主体） |
| 64 维特征（满幅随机） | 0.145 dB |
| 64 维特征（真实量级） | **0.076 dB（8.5%）** |

意义：那 64 维是**自由特征槽**。我们填自己的特征（或先填 0），曲线照样成立；
这直接把"逆向特征提取"这个最深的坑绕过去了，也让插件可以解释、可以调。

### 2. 有 390 条真实曲线做兜底与回归

`ai_curve_table.json` = 16 情绪 × 26 流派里非全零的 390 条「与歌曲无关的先验曲线」。

意义：
- 提取不出特征时，退化成"情绪+流派的先验"，已经比固定预设好；
- 可以做**确定性回归测试**：同一输入必须得到同一条曲线。

### 3. 完全离线、零隐私风险

- 不调用任何第三方接口；
- 不上传音频、不上传特征、不上传曲线；
- 断网可用；
- 推理在本地，单次 < 10 µs，可以忽略。

## 三、和常见做法比

| | 固定预设（现有播放器） | 云端大模型 | 原版 MNN 模型 | **本插件** |
|---|---|---|---|---|
| 随歌变化 | ❌ 一首歌一套 | ✅ | ✅ | ✅ |
| 需要联网 | ❌ | ✅ 必须 | ❌ | ❌ |
| 延迟 | 0 | 数百 ms ~ 秒级 | 0 | **< 10 µs** |
| 体积 | ~0 | 0（但吃流量） | 553 KB + MNN 运行时 | **590 KB JSON，零依赖** |
| 可解释 | 低 | 低 | 低 | **高**（情绪/流派/曲线都能显示） |
| 可二次创作 | ❌ | ❌ | ❌ | **✅**（曲线可分享、可叠偏好） |
| 隐私 | 好 | 差 | 好 | **好** |

## 四、能直接放进描述的三段文案

**短（一行）**
> 每首歌进来，本地几十微秒算出一条属于它的 EQ 曲线——不联网、不上传、不打断播放。

**中（商店卡片）**
> 用一条 0.4 dB 精度的轻量模型，按歌曲的情绪与风格生成专属 EQ 曲线。
> 全部本地计算（单次 < 10 µs，590 KB 权重，零依赖），断网可用，不采集任何数据。

**长（详情页）**
> 大多数"音效"是固定的：一首歌用一个预设，切歌还得手动换。
> 这个插件把"这次听什么"交给模型：判定当前歌曲偏厚/偏亮/偏人声，再给出 10 段目标曲线，
> 由播放器实时执行。模型只有 590 KB、单次推理不到 10 微秒，跑在本地，不联网、不上传。
> 曲线你可以自己再叠一层偏好（低频/现场感/人声），也可以存下来分享给朋友。

## 五、诚实说局限（别在描述里吹过头）

| 局限 | 说明 |
|---|---|
| 只有 10 段、±12 dB | 做不了精细的参量 EQ 或动态处理（需要宿主扩 API） |
| 流派判定是 best-effort | 频谱描述"现在什么样"，预设描述"该怎么补偿"，语义不同；我们靠元数据/用户选择/阈值兜底 |
| 情绪索引的**名字**未证实 | 曲线数值有效，标签文案可能错位；建议用"厚低/中频/明亮"这类形状描述，不硬编情绪名词 |
| 原始曲线很淡（±1.7 dB） | 人耳不明显，产品上需要「强度」倍率（默认 160%） |
| 分发限制 | 原版 `emofxnet.mnn` 是官方资产，**不能随插件分发**；分发用蒸馏权重或自训模型 + 曲线表 |
