# 中文版（投到 chthollyphile/folia-major 的 Issues）

**标题**：`[Feature] 给模组一个音频效果入口（folium.audio.*）：目前只能分析，不能参与声音`

---

## 背景

我在做一个 Folium 模组：**按当前歌曲自动匹配音效 / EQ**（类似网易云的「AI 调音」：判定情绪与风格 → 给出一条目标曲线 → 交给宿主执行）。曲线是每首歌一条、切歌时确定，不是逐帧变化。

做下来发现卡在一个地方：**模组能读到音频分析数据，但没有任何办法参与声音本身**。

## 现状（`ctx.audio` 只读）

- `ctx.audio.getSpectrum() / getBands() / getPower()` 很好用，足够做分析；
- 但没有对应的写入通道；
- `folium.internals` 里只有 `playback / appView / visualizerSettings / themeSettings / lyricSettings`，没有音频相关的 store，且 `internals` 已列入 Folium 2 的移除名单，不适合作为方案。

结果是：模组只能「建议」，没法「执行」。用户必须手动把 10 个数字抄进设置面板，这件事把这类模组的体验卡死在半路。

## 我观察到的宿主机架（普通用户也能看到的信息）

渲染进程控制台里宿主会打印自己的音频图：

```
graph: decks -> mix -> equaliser -> effects -> volume -> fade -> analyser -> out
```

对应的界面是「设置 → 音频效果器」：

- 10 段增益：31 / 62 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k Hz，±12 dB，带 6 个预设 + 自定义 1 / 自定义 2；
- 效果链：低频截止、高频截止、饱和失真、比特降解、抖动、黑胶噪声、立体声宽度、空间混响、动态压缩；
- 输出设备走 `AudioContext.setSinkId`。

也就是说，**宿主已经有完整的执行器**，缺的只是一个让模组把参数递进去的入口。

## 提案：三档，任选其一都能解决 90% 的需求

我按「实现成本」排序，任何一档落地都够用：

### 方案 A（最小，推荐先做）：让模组写宿主的 EQ / 效果参数

```js
const audio = folium.experimental['audio.mix'];      // 或稳定服务 folium.audio

audio.getMix();                                      // { equalizer: {enabled, gains[10], preset}, effects: {...} }
audio.setEqualizer({ gains: [/* 10 个 dB */] });      // 复用宿主现有的平滑，不产生咔嗒
audio.setEffects({ width: 1.2, reverb: 0.15 });      // 可选
```

要点：

- 写入走宿主**已有的**平滑与限幅逻辑，模组不需要自己处理交叉淡化；
- 只改参数，不改滤波器结构，风险低；
- 可以只支持 `setEqualizer` 一个方法，也足够支撑「自动 EQ / 自动音效」这一类模组。

### 方案 B（能力最强）：允许模组往链路里插一个 AudioNode

```js
folium.experimental['audio.chain'].insert((ctx) => myNode, { slot: 'post-mix' });
```

这条能让模组做宿主没有的效果（多段压缩、卷积混响、空间化），但需要宿主定义 slot 与生命周期，成本明显更高。**不建议第一步就做**。

### 方案 C（最保守）：只允许模组「请求切换预设」

```js
folium.audio.applyPreset('custom-1');   // 只切宿主已有的槽位
```

如果 A 因为设计取舍不方便，C 也能让「模组算出曲线 → 用户预先存成槽位 → 模组切槽位」这条链路跑起来。

## 为什么值得做（不止我这个模组）

现在 Folium 的模组生态基本集中在「视觉层」（歌词动画、背景、进度条、面板）。音频侧一旦有 A 这一档，能开出一整类模组：

- 按歌曲内容自动匹配音效 / EQ；
- 助听 / 频响补偿（用户听力曲线不同）；
- 夜间／通勤场景的响度均衡；
- 播客 / 有声书的人声增强。

这些全部**纯本地、不联网、不导出音频**，和现有安全模型不冲突。

## 我可以配合的部分

- 所有接口标 `experimental`、随时改都可以，我不要求稳定承诺；
- 需要的话我可以提交 PoC 模组 + 测试用例；
- 我这边已经实现的平滑策略（增益一阶低通 τ≈150 ms、曲线切换 300 ms 等功率交叉淡化）可以直接抄。

## 边界声明

- 不会导出 provider 的原始音频流或解密后的音频文件；
- 不调用任何第三方接口；
- 只在用户显式启用并确认后注册，不后台运行。

谢谢。
