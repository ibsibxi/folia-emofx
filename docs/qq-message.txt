你好，打扰一下。我是 Folia 的用户，最近在做 Folium 模组——就是「按当前歌曲自动匹配音效 / EQ」那种（判定情绪和风格，给出一条目标曲线）。

做的过程中卡在一个地方想请教你：

模组现在能通过 ctx.audio 拿到实时频谱做分析，这部分很好用；但没有办法把结果写回宿主的音频链。也就是说模组只能"建议"一条曲线，没法让它自动生效，用户还得手动把 10 个数字抄进设置面板——这一下就把体验卡死了。

宿主的「音频效果器」面板里其实已经有完整的执行器（10 段增益 + 低切/高切/饱和/宽度/混响/压缩），所以想问问：

有没有可能给模组开一个最小的写入入口？比如
  folium.audio.setEqualizer({ gains: [10 个 dB] })
只写参数、复用你们现有的平滑与限幅，不需要模组自己处理交叉淡化。哪怕只支持这一个方法，也足够支撑这类模组了。

如果要更保守，只允许「切换预设槽位」也行（applyPreset），我能把曲线预先存成两个自定义槽位再切换。

我这边可以全程标 experimental、随时改、不要求稳定承诺；也能提供 PoC 模组和测试用例。不做音频导出、不联网、不调用任何第三方接口。

需要的话我可以直接开 issue 把细节和证据写清楚。谢谢！

版 2 · 他问细节时再发（长，分条）
════════════════════════════════════════

1）我在做什么
   一个 Folium 模组：情绪 + 风格 → 一条 10 段目标曲线（每首歌一条，切歌时确定，不是逐帧变化）。
   分析侧用 ctx.audio 已经跑通；缺的是执行侧。

2）现状：只能读，不能写
   · ctx.audio.getSpectrum / getBands / getPower  只读，够用
   · 没有写入通道
   · folium.internals 里只有 playback / appView / visualizerSettings / themeSettings / lyricSettings，没有音频 store；
     而且 internals 已列进 Folium 2 的移除名单，不适合当方案

3）宿主其实已经有执行器（用户也能看到）
   渲染进程日志里宿主会打印自己的图：
     graph: decks -> mix -> equaliser -> effects -> volume -> fade -> analyser -> out
   界面上是「设置 → 音频效果器」：
     · 10 段：31 / 62 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k Hz，±12 dB，6 个预设 + 自定义 1 / 2
     · 效果链：低频截止、高频截止、饱和失真、比特降解、抖动、黑胶噪声、立体声宽度、空间混响、动态压缩
     · 输出走 AudioContext.setSinkId
   也就是说执行器已经齐全，缺的只是一个模组侧入口。

4）三档提案，任选其一我都够用
   A（最小，推荐）：只写 EQ 参数
       const audio = folium.experimental['audio.mix'];
       audio.getMix();                                // { equalizer: { enabled, gains[10], preset }, effects }
       audio.setEqualizer({ gains: [...] });           // 走宿主现有平滑
       audio.setEffects({ width: 1.2, reverb: 0.15 }); // 可选
       要点：只改参数、不改滤波器结构；平滑/限幅由宿主负责，模组不重复实现。

   B（最强，先别做）：允许插一个 AudioNode
       folium.experimental['audio.chain'].insert(ctx => myNode, { slot: 'post-mix' });
       能做宿主没有的效果（多段压缩、卷积混响），但要设计 slot 和生命周期，成本高。

   C（最保守）：只允许切预设
       folium.audio.applyPreset('custom-1');
       也够跑「模组算曲线 → 用户预存成槽位 → 模组切槽位」这条链路。

5）为什么不止为我一个模组
   现在模组生态几乎全在视觉层（歌词、背景、进度条、面板）。有 A 这一档就能开出一类音频模组：
   · 按歌曲内容自动匹配音效 / EQ
   · 助听 / 频响补偿（每个人听力曲线不同）
   · 夜间、通勤场景的响度均衡
   · 播客 / 有声书的人声增强
   全部纯本地、不联网、不导出音频，和现在的安全模型不冲突。

6）我能配合的部分
   · 全部标 experimental，随时改
   · 提供 PoC 模组 + 测试
   · 我这边已实现的平滑策略可以直接抄：增益一阶低通 τ≈150 ms；曲线切换 300 ms 等功率交叉淡化

7）边界
   · 不导出 provider 原始音频流或解密后的音频文件
   · 不调用任何第三方接口
   · 用户不显式启用并确认就不注册、不后台跑

版 3 · 他可能追问，怎么答（你自己看，不要发）
════════════════════════════════════════

Q：你为什么不直接开 issue？
A：可以，我马上开；先在 QQ 上问一句是怕需求本身不合适，浪费你的时间。

Q：为什么不用 internals？
A：试过。internals 没有音频 store，而且已经列进 Folium 2 移除名单，我不想做个一年后必死的东西。

Q：这个接口会不会被滥用（比如导出音频流）？
A：写入接口只能改参数，拿不到音频数据；而且我建议顺手在文档里写明「只允许改参数、不允许取流」。

Q：实现起来麻烦吗？
A：最小档（setEqualizer）只需要把已有的 setter 暴露一层，外加数值夹紧；模组侧我可以标 experimental。

Q：能不能你自己实现 / 提交 PR？
A：可以，如果你告诉我改哪个文件、怎么走你们的注册表约定，我可以试着提 PR；不行的话我出 PoC 给你参考。

Q：有别的模组需要这个能力吗？
A：目前没见到公开的（因为做不到）。这也是我写提案的原因——现在没人做，是缺接口，不是没需求。

Q：你的模组叫什么、能看看吗？
A：还没发布（卡在这个接口上）。可以先给你一个本地 PoC，展示"算出一条曲线并显示"，等接口有了再做执行侧。
